# B1-1 — 사전 학습 역량 진단 설계 (02단계)

> **ASSESSMENT_DESIGN=PREPARED / LEARNER_RESULT=NOT_VERIFIED.** 2026-10-26 기준 문항·채점 원칙만 설계. 실제 학습자의 답을 받거나 독립 학습 숙달을 평가하지 않았습니다. 이전 차수의 시험·설명을 이번 학습자 점수로 재사용하지 않습니다.

## 먼저 읽기 — 평가가 아니라 출발점을 찾는 도구입니다

학습을 시작할 때 **모르는 항목은 표시**하면 됩니다. '정답을 빨리 외우기'보다 **두 문장으로 설명하고 입력→처리→예상 결과를 그려보는 것**을 목표로 합니다.

학습 유형은 ① 용어 ② 원리 ③ 코드 결과 예측 ④ 오류 해결 ⑤ 공식 요구 이해입니다. **사전(Pre)과 사후(Post)는 동일 역량·동등 난도**를 목표로 별도 문제 세트를 구성합니다.

## 입문자가 혼자 따라가는 학습·진단 순서 (실제 시행 전)

1. **읽기:** [02단계 README](README.md)의 **B. 기술 배우기**에서 용어 → 개념 → 비유 → Mermaid → 코드 → 흐름 → 오류 해결 → 실습 → 평가 순서를 확인합니다.
2. **이해:** 용어를 암기하지 말고 한 문장으로 풀이합니다. 예: HTML은 구조, CSS는 모양, JavaScript는 동작.
3. **설명:** 코드를 보지 않고 “클릭 → 이벤트 → 상태 → DOM 변경 → 화면 표시”를 두 문장으로 이야기합니다.
4. **재현:** 종이에 테마 버튼을 0회·1회·2회 클릭했을 때 상태와 문구를 그립니다. 실제 컴퓨터 실행은 하지 않습니다.
5. **자기 점검:** 아래 A01~A10에서 모르는 문항은 표시만 합니다. 실제 평가를 수행한다면 답안 수집·채점 전 **평가 기준, 개인정보 범위와 학습자 동의**를 확인해야 합니다.

**도움이 필요할 때:** 모르는 용어는 [용어집](../00-plan/TECHNICAL-GLOSSARY.md), 코드 원리는 [02단계 대표 사례](README.md#stage02-review), 차수별 증거 구분은 [기존 소스 목록](LEGACY-ASSET-MATRIX.md)으로 돌아가세요.

**종이 재현 과제:** 실제 코드 없이 테마 클릭→상태 변경→CSS 적용→브라우저 저장의 **예상 흐름**을 도식화합니다. 새로운 Round 04 코드가 실행된 것은 아닙니다.

## 3. 채점·도움 수준 (계획만 작성)

| 영역 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 정의와 정확성 | 설명 없음·틀림 | 핵심 일부 맞음 | 뜻·역할·조건이 정확함 |
| 원리·이유 설명 | 원인/목적 불명 | 일부 절차 설명 | 단계·이유·한계까지 설명 |
| 재현·오류 분석 | 흐름 구성 못함 | 핵심 일부 연결 | 입력→처리→출력·실패 경로 설명 |

실제 평가 시에는 **각 문항에 적용할 채점 기준과 만점, 답안 예시를 일관되게 정한 뒤**, 독립 평가자가 검수합니다. 이 표는 현재 학습자 점수의 산정 결과가 아닙니다.

**힌트 단계:** H1 질문 → H2 개념 → H3 절차 → H4 해설. 힌트 없이 한 설명인지 반드시 구분하고 사전·사후 비교 시 도움 정도를 기록합니다.

**L1~L5**는 실제 독립 수행이 관찰된 후만 판정: L1 코드 보며 설명 / L2 그림만 보고 설명 / L3 자료 없이 설명 / L4 빈 환경에서 구현 / L5 새 문제 해결. 지금 단계에서 **MASTER 선언 금지**.

### 채점 방식 예시 (설계안, 실제 점수 아님)

**한 문항의 계획 만점은 6점**으로 고정합니다. ① 용어·정의 0~2점, ② 이유·원리 0~2점, ③ 예측·재현·오류 분석 0~2점을 각각 채점합니다. **10문항 합계는 60점**입니다. 기술적으로 재현하기 어려운 질문에도 “예상 결과 또는 실패 경로를 설명했는지” 기준을 적용하며, 실제 시행 전 문항별 모범 답안·평가자 일치도를 검토해야 합니다.

| 기록 항목 | 기록 예시(빈 양식) | 유의점 |
|---|---|---|
| 문항 ID | A04 / B04 | 서로 대응하는 역량인지 확인 |
| 개념 점수 | __ / 2 | 0·1·2점의 구체적 이유 기록 |
| 원리 점수 | __ / 2 | 왜 그런지 설명했는지 |
| 재현 점수 | __ / 2 | 입력→상태→화면과 오류를 연결했는지 |
| 도움 수준 | 없음 / H1 / H2 / H3 / H4 | 도움 없이 독립 수행한 결과와 구분 |
| 증빙 형태 | 말로 설명 / 종이 그림 / 별도 승인 후 실행 | 종이 재현을 코드 실행 PASS로 기록하지 않음 |

**예시 정답(연습용, 평가 결과 아님):** A01은 “HTML=내용과 구조, CSS=표현, JavaScript=사용자 반응”; A04는 “클릭 감지 → 상태 변경 → DOM/CSS 반영 → 화면 확인”; A06은 “선택자가 실제 요소를 찾았는지 먼저 확인”; A07은 “정상 빈 배열과 HTTP 403 오류는 다른 상태”; A10은 “차수·출처·코드 SHA·실행 시점이 다르기 때문”입니다.

**학습 효과 판정 조건:** 실제 사전·사후 답안을 수집하고 동일 기준으로 채점했을 때만 점수 변화와 숙달 수준을 판단합니다. 이 문서만 완성됐다고 **LEARNER_RESULT=PASS** 또는 **L4/L5 MASTER**로 선언하지 않습니다.
