# B1-1 Round 04 Agent — GitHub Markdown 실제 화면 QA 기록

> 검사일: **2026-10-26** · 대상: `00-plan/README.md`, `MASTER-PLAN.md`, `STAGE-00-MERMAID-GUIDE.md`  
> **실제 GitHub 페이지의 시각 검수: NOT_VERIFIED** — GitHub 화면을 가져오지 못했기 때문입니다. 태그의 소스 구조 검증 PASS와 혼동하지 마세요.

## 1. 검사 목표

GitHub의 **밝은 테마·어두운 테마** 및 **데스크톱 너비 1280px·모바일 너비 375px**에서 형광펜 색상·글자 대비·밑줄·줄바꿈·표·Mermaid 그림이 실제로 읽히는지 확인하려 했습니다.

## 2. 실제 접근 결과

| 검사 경로 | 수행 내용 | 직접 확인 결과 |
|---|---|---|
| 현재 컨테이너 | 공개 GitHub URL 대상으로 `curl -IL` | **DNS 실패**, `Could not resolve host: github.com` |
| WSL2 Ubuntu / Agent Codyssey MCP | GitHub URL에 `getent ahosts`, `curl` 읽기 전용 검사 | **DNS 실패**, `curl exit 6`, HTTP `000` |
| Chrome for Testing | WSL2에 기존 `153.0.8010.12` 바이너리 확인 | 브라우저 **설치 여부만 확인**; 실제 페이지 렌더링 미수행 |
| GitHub 페이지 스크린샷 | 라이브 DOM 렌더 및 픽셀 캡처 | **NOT_CAPTURED / NOT_VERIFIED** |

접근 장애가 있으므로 GitHub 화면에서 색상을 직접 보았거나, 대비율을 측정했거나, 모바일 스크롤을 검사했다고 기록하지 않습니다. 레포 파일·Git 설정·서비스·실행 코드는 점검 목적으로 변경하지 않았습니다.

## 3. 정적 소스 검증 결과

| 파일 | `<mark>` 형광펜 | `<ins>` 밑줄 | 태그 짝 검증 | Mermaid |
|---|---:|---:|---|---:|
| [입문자 README](README.md) | 5 | 5 | PASS | 1개 |
| [고정 개발계획](MASTER-PLAN.md) | 4 | 6 | PASS | 없음 |
| [Mermaid 입문 설명서](STAGE-00-MERMAID-GUIDE.md) | 3 | 2 | PASS | 3개 |
| **합계** | **12** | **13** | **PASS (정적)** | **4개** |

- 임의의 `style=` 속성 사용: **없음**. GitHub에서 사용자 지정 형광펜 색상을 보장할 수 없습니다.
- 형광펜·밑줄 시작/종료 태그 개수: **일치**. 그러나 실제 GitHub HTML/스타일 계산 결과는 미확인입니다.
- Markdown 표: README **35행**, MASTER-PLAN **38행**, Mermaid 설명서 **34행**(구분선 포함)이며, **375px에서 가로 스크롤 또는 표가 잘리는지 실제 확인 필요**.
- GitHub 공식 문서는 `<ins>` 밑줄을 안내하고 있으며, `<mark>`는 HTML/GFM 렌더러에서 허용될 수 있으나 실제 화면의 색상·테마별 스타일은 실측이 필요합니다.
- **문서 소스 작성 검증 PASS ≠ 시각적 가독성 PASS**입니다.

## 4. 화면 크기·테마 검사표

| 테마 | 화면 너비 | 핵심 확인 항목 | 상태 |
|---|---:|---|---|
| Light | 1280px | 형광펜 배경·글자색, 밑줄, 표, Mermaid | NOT_VERIFIED |
| Light | 375px | 글자 줄바꿈, 모바일 표 가로 스크롤, Mermaid 폭 | NOT_VERIFIED |
| Dark | 1280px | 형광펜/본문 대비, 밑줄, 표, Mermaid | NOT_VERIFIED |
| Dark | 375px | 강조 가독성·표 잘림·도식 확대 가능 여부 | NOT_VERIFIED |

WCAG 2.2의 일반 텍스트 대비 기준 **4.5:1**(큰 텍스트는 **3:1**)을 점검 기준으로 계획하지만, 실제 computed `color`와 `background-color` 값이 확보되지 않아 **대비율을 계산하거나 합격 선언하지 않습니다.**

## 5. 실제 브라우저 검수에 필요한 순서

1. [실제 GitHub README](README.md), [개발계획](MASTER-PLAN.md), [Mermaid 설명서](STAGE-00-MERMAID-GUIDE.md)를 GitHub **Preview 화면**으로 엽니다(`Raw`나 `Code` 보기와 구분).
2. GitHub **Light** 테마에서 1280px 및 375px 화면을 촬영합니다. 형광펜, 밑줄, 좁은 표의 스크롤 상태, Mermaid 글자를 확인합니다.
3. **Dark** 테마에서도 동일하게 검사합니다. 글자 대비·강조색·표·도식이 가려지거나 서로 혼동되지 않는지 확인합니다.
4. 페이지 실제 HTML 요소의 CSS `color`, `background-color`, `text-decoration` 값을 읽고 WCAG 대비율을 계산합니다.
5. 각 조건의 브라우저 캡처·테스트 시각·GitHub 기준 Commit SHA를 기록하고 **실제 사용자 시각 검수**를 거친 뒤 결과를 PASS/FAIL로 판정합니다.

**최종 판정:** GitHub Markdown 원문 강조 태그의 **정적 정확성 PASS**, **실제 화면 시각·대비·가독성 NOT_VERIFIED**. 네트워크 장애를 해결하거나 실제 화면 증빙을 제공받기 전에는 `VISUAL_QA=PASS`로 변경하지 않습니다.
