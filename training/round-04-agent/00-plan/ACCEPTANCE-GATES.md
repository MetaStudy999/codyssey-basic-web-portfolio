# B1-1 Round 04 Agent — 단계별 PASS/FAIL 게이트 V1.0

> 상태 표기: **PASS** = 직접 읽기·실행·검증한 근거가 기준을 충족. **FAIL** = 재현 가능한 실제 불충족. **NOT_VERIFIED** = 아직 검증 전/증거 부족. 과거 Round PASS는 신규 Round 04 PASS가 아닙니다.

| 단계 | PASS(필수 기준) | FAIL(실제 오류) | 현재 상태 |
|---|---|---|---|
| 00 계획 | 고정 목표·00~09 목차·의존성 일정·승인 경계·산출물·판정 기준이 저장소에 존재 | 필수 계획 누락·모순 | DOCUMENT_READY (커밋 검증 후 PASS) |
| 01 요구 | 공식 미션 PDF·공식 평가 15문항을 근거와 함께 매핑 | 공식 필수 조항 빠짐/오인 | NOT_VERIFIED |
| 02 분석 | 이전 차수·루트 원본과 현재 실제 상태·미완료 차이 구분 | 누락/역사적 PASS를 새 PASS로 오기 | NOT_VERIFIED |
| 03 설계 | 신규 구현과 상태·오류·반응형·시험 계획이 공식 필수항목을 모두 커버 | 공식 필수 기능 누락 | NOT_VERIFIED |
| 04 구현 | 승인된 새 HTML/CSS/JS 코드가 `04-src/`에 있고 필수 기능 실현 | 코드 부재/기능 누락/승인 없는 변경 | NOT_STARTED |
| 05 시험 | 실제 Chrome/Chromium 화면, 반응형, 이벤트, API 오류, 폼, 테마, 회귀가 충족 | 재현된 테스트 실패 | NOT_VERIFIED |

| 07 평가 | 공식 평가 문항 15개 설명과 구현 근거 연결 | 필수 문항 설명 불충분 | NOT_VERIFIED |
| 08 발표 | PPTX/PDF 16장 구성·내용 일치·읽기·시각 근거 검수 | 누락·오표기·읽기 실패 | NOT_VERIFIED |
| 09 인계 | 최종 코드·증빙·최종 판정·GitHub 상태·재현 절차 기록 | 누락·미확인 PASS 선언 | NOT_VERIFIED |

## 실행 승인

- **00~03**: 미션 계획·요구·기존 자료 비교·신규 설계 문서 작업. 사용자의 '단계별로 하나씩'에 따라 매 단계 실제 작업 후 보고.
- **04**: 신규 코드 작성·명령 실행 전 사용자 **명시적 개발 승인 필수**. 지금까지의 경로 생성 및 문서 작성은 이 승인을 의미하지 않음.
- **05~06**: 기존 기능 테스트를 새 Round 결과로 오인하지 않으며, 새 코드의 실제 실행과 필요 시 공개 배포는 실행 범위·승인 및 권한 확인 후 실시.
- **07~09**: 실제 사용자 설명이 필요한 평가 문항을 임의로 PASS 처리하지 않음. 프로덕션 전환·브랜치 병합·운영 변경은 승인 필요.

## 전역 보호

- WSL2 Codex, GitHub 기존 브랜치, Round 01~03 증빙, Pages 이전 URL 및 기능 보존.
- 현재 루트 `index.html`은 **안내 페이지**. 새 미션 산출물 `04-src/index.html`과 혼동 금지.
- 과거 `FINAL_CLEAR` 증거를 변경하지 않음.
- 토큰·비밀키·개인정보 원문을 코드·로그·증빙에 저장하지 않음.
- 실행 불가 및 비검증은 `NOT_VERIFIED`로 보고; 추정 PASS/CLEAR 선언 금지.

## 단계별 리포트 형식

`단계 | 실제 수행 | 근거 파일/도구 응답/커밋 SHA | PASS/FAIL/NOT_VERIFIED | 미완료/차단 요인 | 다음 단계를 위한 조건`.
