# B1-1 — 공식 미션 요구사항 추적표 (01단계)

> **근거:** [제2기 B1-1 미션 PDF 9쪽](https://drive.google.com/file/d/1YC6KKj-hCi54FzOhivZmetX0EQXFXXNy/view) · **확인일 2026-10-26** · **01단계 문서 분석 기준**. 실제 신규 소스·실행·배포 결과는 미생성입니다.

## 먼저 읽기

이 표는 공식 미션의 10개 기능 요구 영역(§4.1~4.10)과 별도 선택 과제(§5), 개발환경·제약(§6~7)을 **작고 검증 가능한 단위**로 풀어 기록한 것입니다. 문장들은 원문을 *의미 단위로 재서술*했으므로 애매하면 PDF 원문을 우선합니다.

- **CORE(필수):** PDF §4의 필수 항목(문장 중 ‘선택’ 명시 제외) 및 핵심 제출 요건.
- **BONUS(선택):** PDF에서 선택으로 명시한 기능. 평가표의 질문은 수행 사실을 확인하기 위한 것으로, 선택을 필수로 자동 변경하지 않습니다.
- **RECOMMENDED(권장):** 기준 수치 등의 권장값. 변경한다면 README에 실제 값을 적어야 합니다.
- **CONSTRAINT(제약):** 사용 금지/허용 범위, **GUIDANCE(안내):** 시점별로 달라질 수 있는 정보.
- **아직 증빙 없음:** 아래 '검증 방법'은 미래에 무엇을 확인할지 정한 수용 계획입니다. 실제 04-src 코드를 확인하거나 테스트 PASS를 주장하지 않습니다.

**분석 결과:** 총 **73개 원자 요구·제약·선택 항목** / 12개 영역. 분류: CORE 59 · RECOMMENDED 1 · BONUS 6 · GUIDANCE 1 · CONSTRAINT 4 · ALLOWED 1 · PRIORITY 1. 정확한 평가 문항 연결은 [E01~E15 매핑](EVALUATION-15-MAPPING.md), 쟁점은 [원문 우선·판단 기록](SOURCE-CONFLICTS-AND-DECISIONS.md)을 참조하세요.

## 평가·증거 연결 규칙

1. **PDF 해당 절 → Rxx-yy**: 각 요구를 고유 ID로 추적하며 CORE/BONUS/제약을 섞지 않습니다.
2. **Rxx-yy → E01~E15**: 15개 평가문항에 관련 요구 ID를 연결합니다. 평가표가 미션 PDF보다 강화된 질문을 포함해도, 사용자 동의 없는 필수 기능 확장으로 간주하지 않습니다.
3. **요구 → 학습 목표 → 설계 → 코드 → 테스트 → 증거**: [학습목표](LEARNING-OBJECTIVES.md)는 01단계에 연결까지 수행; 실제 코드 경로와 커밋 SHA는 04~06단계의 실증 뒤 기록합니다.
4. **진입·종료 구분:** 본 문서가 존재하고 원문과 구조가 정합하면 **01 요구 분석 문서 PASS 후보**입니다. 미션 기능 PASS, QG-01 실제 수행, 공식 평가 완료, 최종 CLEAR는 전부 별개입니다.
