# 빠른 학습 체계 — B1-1 적용본

기억에 의존하는 암기가 아니라 **쉬운 비유 → 정의 → 실제 코드 → 화면 → 직접 설명 → 재현**으로 진행한다.

| 학습 단위 | 쉬운 설명 | 코드·검증 위치 | 직접 확인할 질문 |
| --- | --- | --- | --- |
| HTML(구조) | 건물의 공간·표지판 | `04-src/index.html` | 왜 header/nav/section을 나누는가? |
| CSS(디자인) | 화면 배치와 색상 규칙 | `04-src/css/style.css` | Flexbox/Grid를 나눠 쓴 이유는? |
| JS(자바스크립트) | 클릭 신호를 화면 변화로 연결 | `04-src/js/main.js` | Event가 State를 어떻게 바꾸는가? |
| DOM(문서 객체 모델) | JS가 다루는 화면 요소의 구조 | `document.querySelector` | 어떤 요소를 찾아 어떻게 바꾸는가? |
| API(응용 프로그램 인터페이스) | 다른 서비스에 데이터를 요청하는 통로 | `loadProjects` | 로딩·성공·오류·빈 상태를 왜 구별하나? |
| 검증 | 눈으로만 보지 않고 재현 가능한 근거 확보 | `evidence/` | 무엇이 실제 PASS를 증명하나? |

## 단계별 개인 학습 검증
- L0: 개념을 보고 이해 (문서만으로 PASS를 자동 선언하지 않음)
- L1: 코드 위치를 찾고 설명
- L2: 자료 없이 동작 흐름 설명
- L3: 힌트를 줄여 핵심 기능 재현
- L4: 비슷하지만 새로운 문제 해결
- L5: 다른 분야로 원리 이전(Transfer)

`LEARNING-GATE.md`의 네 답변은 **최소 구술 확인 PASS**다. L3~L5의 실기·전이 능력은 아직 측정하지 않았다.

## 설명 정책
용어는 한글 + 영어 + 약어를 병기한다. 기술 개념은 필요 시 4컷 만화, 세로 흐름도, 실제 소스와 연결한다. 생성 이미지와 검증 사진은 절대 혼동하지 않는다.
